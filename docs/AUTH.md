# Authentication and Authorization Specification — CapstoneHub

This document outlines the authentication architecture, token mechanisms, storage patterns, authorization middleware behavior, and security conventions for CapstoneHub.

---

## 1. Overview

CapstoneHub uses **JSON Web Token (JWT)** based authentication. The server is stateless and does not maintain server-side sessions. All authentication data is self-contained within the signed JWT token.

- **Token Format**: Standard HS256 signed JSON Web Token.
- **Default Expiration**: 7 days (`JWT_EXPIRES_IN=7d`).
- **Secret Key**: Defined via `JWT_SECRET` in environment variables.

---

## 2. Authentication Flow

### A. Registration Flow
- **Endpoint**: `POST /api/auth/register`
- **Payload**:
  ```json
  {
    "email": "student@example.com",
    "password": "Password123!",
    "name": "Jane Student",
    "role": "TEAM_MEMBER" // Optional: "TEAM_MEMBER" (default) or "FACULTY"
  }
  ```
- **Process**:
  1. Validates email syntax (`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`).
  2. Enforces password minimum length of 6 characters.
  3. Normalizes email to lowercase.
  4. Hashes password using `bcryptjs` (salt rounds: 10).
  5. Creates `User` record in PostgreSQL database.
  6. Generates JWT token containing `{ id, email, role }`.
  7. Returns HTTP 201 with `{ success: true, data: { user, token } }`.

### B. Login Flow
- **Endpoint**: `POST /api/auth/login`
- **Payload**:
  ```json
  {
    "email": "student@example.com",
    "password": "Password123!"
  }
  ```
- **Process**:
  1. Normalizes email to lowercase.
  2. Queries user by email.
  3. Verifies hash via `bcrypt.compare`.
  4. Generates signed JWT token.
  5. Returns HTTP 200 with `{ success: true, data: { user, token } }`.

---

## 3. JWT Token Structure & Payload

The JWT token generated by `AuthService.generateToken()` contains the following decoded payload:

```json
{
  "id": "u1a2b3c4-5678-90ab-cdef-1234567890ab",
  "email": "student@example.com",
  "role": "TEAM_MEMBER", // "TEAM_MEMBER" | "TEAM_LEAD" | "FACULTY"
  "iat": 1789150000,
  "exp": 1789754800
}
```

---

## 4. Including Token in HTTP Requests

Every request to protected endpoints (`/api/projects/*`, `/api/requirements/*`, `/api/deliverables/*`, `/api/bugs/*`, `/api/faculty/*`, etc.) must include the token in the standard HTTP `Authorization` header:

```http
Authorization: Bearer <JWT_TOKEN_STRING>
```

### Example Axios Interceptor (Frontend Implementation Pattern):
```typescript
import axios from 'axios';

const api = axios.create({
  baseURL: 'http://localhost:5001/api',
});

api.interceptors.request.use((config) => {
  const token = localStorage.getItem('capstonehub_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

export default api;
```

---

## 5. Token Storage Expectations

- **Browser Storage**: Store token string in `localStorage` under key `capstonehub_token` (or in React auth state).
- **User Object**: Store the `user` object (`{ id, name, email, role }`) in application state (e.g. Zustand, Redux, or React Context) upon successful login or registration.

---

## 6. Authentication Middleware Logic

Backend authentication is handled by `authenticate` middleware (`backend/src/middleware/auth.ts`):

```typescript
// Conceptual steps executed on every protected route:
1. Extract Authorization header from HTTP Request.
2. Verify format starts with "Bearer ".
3. Verify JWT signature using config.jwtSecret.
4. If valid, set req.user = { id: payload.id, email: payload.email, role: payload.role }.
5. Call next().
6. If missing, invalid, or expired: return HTTP 401 Unauthorized:
   { "success": false, "error": "Invalid or expired token" }
```

---

## 7. Role Retrieval & Authorization Checks

- **Role Extraction**: `req.user.role` supplies user role (`TEAM_MEMBER`, `TEAM_LEAD`, `FACULTY`).
- **Dynamic Team Lead Role**: A user whose base role is `TEAM_MEMBER` can act as `TEAM_LEAD` for a specific project if `project.team.leadId === user.id` or if `team_members` entry has `role === 'TEAM_LEAD'`.
- **Faculty Guard**: Middleware checks `req.user.role === 'FACULTY'`. If false, returns `HTTP 403 Forbidden`.

---

## 8. Logout Behavior

Since the backend is stateless:
- **Logout Action**: Purely client-side. Clear token and user object from `localStorage` / state.
- Redirect user to `/login`.

---

## 9. Token Expiration Handling

- When a request receives `HTTP 401 Unauthorized` with error `"Invalid or expired token"`, the frontend should clear stored token and redirect the user to `/login`.
